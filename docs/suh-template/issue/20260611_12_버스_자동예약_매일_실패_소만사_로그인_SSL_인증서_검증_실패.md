🗒️ 설명
---

버스 자동예약을 켜놓았으나 매일 아침 확인하면 예약이 되어 있지 않다. 예약 시도가 **100% 실패**한다.

원인은 스케줄러가 아니라 **소만사 사이트 로그인 단계의 SSL 인증서 검증 실패**다.

- 자동예약 스케줄러는 정상 실행된다 (매일 `06:00` 레거시 자동예약, `00:13` 3일 후 예약).
- 예약 직전 `LoginOkhttpService.login()`이 소만사 로그인 페이지(`https://cs.android.busin.co.kr/Login.aspx`)로 HTTPS GET을 보낼 때 아래 예외가 발생한다.

```
javax.net.ssl.SSLHandshakeException: PKIX path building failed:
  sun.security.provider.certpath.SunCertPathBuilderException:
  unable to find valid certification path to requested target
```

- 그 결과 `AutoReservationService`가 "로그인 실패, 예약 중단"으로 전체 예약을 건너뛴다.

**근본 원인**

- 소만사 서버 인증서가 **2026-03-16에 `Sectigo Public Server Authentication CA DV R36`** 으로 교체됨 (유효기간 2026-03-16 ~ 2026-09-30).
- 컨테이너 JVM truststore(cacerts)에 해당 Sectigo 중간/루트 CA가 없어 인증서 체인을 신뢰하지 못함.
- `CommonHttpClient`의 `OkHttpClient`에는 SSL 검증 우회(`X509TrustManager`) 설정이 git 히스토리 전체에서 한 번도 존재한 적이 없음. 인증서 교체 전에는 JVM 기본 신뢰 CA로 통과했으나, 교체 이후 깨짐.

**영향 범위**

- `CommonHttpClient.getClient()` 는 로그인 / 세션 / 예약 서비스가 모두 공유한다 (`LoginOkhttpService`, `SessionOkhttpService`, `ReservationOkhttpService`). 로그인이 막히면 전체 예약 흐름이 중단된다.

🔄 재현 방법
---

1. 컨테이너(`somansa-bus-auto-back`)에서 자동예약 스케줄러가 실행되는 시각까지 대기 (또는 로그인 트리거).
2. 로그 확인 시 아래 흐름이 반복됨.

```
AutoReservationService : 레거시 자동 예약 시작
AutoReservationService : 사용자 chan4760@somansa.com 버스 예약 시작: 07:05 군자 1호 - 출근
LoginOkhttpService     : 로그인 시작: chan4760@somansa.com
ERROR LoginOkhttpService     : 로그인 페이지 GET 중 예외 발생
        javax.net.ssl.SSLHandshakeException: PKIX path building failed
ERROR AutoReservationService : 로그인 실패, 예약 중단: chan4760@somansa.com
AutoReservationService : 레거시 자동 예약 완료, 결과: 실패
```

(군자 1호/2호 출근, 1호/2호 퇴근 등 모든 버스편에서 동일하게 실패)

3. 인증서 직접 확인:

```
$ echo | openssl s_client -connect cs.android.busin.co.kr:443 \
    -servername cs.android.busin.co.kr 2>/dev/null \
    | openssl x509 -noout -issuer -subject -dates

issuer=C = GB, O = Sectigo Limited, CN = Sectigo Public Server Authentication CA DV R36
subject=CN = cs.android.busin.co.kr
notBefore=Mar 16 00:00:00 2026 GMT
notAfter=Sep 30 23:59:59 2026 GMT
```

✅ 예상 동작
---

- 스케줄러 실행 시 소만사 로그인이 정상 성공하고, 지정된 버스편 예약이 완료되어야 한다.
- 소만사가 인증서를 다시 교체하더라도 예약 흐름이 깨지지 않아야 한다.

- **대상 사이트**: `https://cs.android.busin.co.kr` (Sectigo DV R36 인증서, 2026-03-16 교체)

🛠️ 해결 방향 (예정)
---

- `CommonHttpClient`의 `OkHttpClient.Builder`에 모든 인증서를 신뢰하는 `X509TrustManager` + `hostnameVerifier`를 적용해 SSL 검증을 우회한다.
- 개인 전용 내부 자동화 도구이며 대상 도메인이 `cs.android.busin.co.kr`로 고정되어 있어, 인증서 재교체에도 안정적인 우회 방식을 채택한다.
- 상세 설계는 brainstorming 단계에서 확정한다.
